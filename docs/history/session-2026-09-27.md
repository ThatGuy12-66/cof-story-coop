## PE relocation fault and byte-exact repair

- **VERIFIED root cause:** The original `push` immediate retained an `IMAGE_REL_BASED_HIGHLOW` relocation for operand RVA **`0x109F07`**. Replacing that instruction with `push 0` and NOPs left the Windows loader authorized to add the base delta into the new instruction bytes.
- **VERIFIED live evidence:** The DLL's preferred base is `0x10000000`; the earlier inspected run loaded it at **`0x68EC0000`**. Although disk bytes at file offset `0x109306` were `6a00909090`, the live bytes at RVA `0x109F06` were **`6a00907ce9`**. The original patch was therefore demonstrably malformed under ASLR. This is independent of the separate missing-WAD fixture error below.
- **VERIFIED repair:** The relocation word at file offset **`0x22E996`** changes from **`073f`** (`0x3F07`, HIGHLOW/type 3) to **`070f`** (`0x0F07`, ABSOLUTE/type 0). The page offset and relocation block size remain unchanged. The corrected patch combines this edit with the existing gate and null-landmark edits. Its complete hash is `942586ABA56AB6C3FAB2DC9F1B4BF42B2DD87E3AF86B67BD29687C507171AFBA`.
- **VERIFIED utility behavior:** `tools/patch_coop.py` recognizes the exact broken hash as a legacy repair input, but cannot select it as an installation target. Dry-run identifies the relocation edit. Restoring either legacy or repaired input reproduces the complete stock bytes and hash `0036B91C01E92ED205513F52563053A55A66A32D257EFB5F476B8F1F3DDE0E63`, including the original relocation.
- **VERIFIED regression tests:** A PE32 loader simulation checks bases `0x10000000`, `0x68EC0000`, `0x00400000`, `0x7F120000`, and `0xE0000000`. Corrected instruction bytes remain `6a00909090`; adjacent real address operands still relocate. A separate regression reproduces the legacy live corruption `6a00907ce9` at `0x68EC0000`.
- **VERIFIED live retest:** Applied at 17:47:29 UTC, then checked in PID 15908 at base `0x68B30000`. The new probe's natural transition to `c_start` completed at 17:48:14 UTC. Its repeated exit succeeded at 17:52:18 UTC, followed by the complete final-chain probe's exit at 17:52:58 UTC. These results supersede the earlier pending status.
