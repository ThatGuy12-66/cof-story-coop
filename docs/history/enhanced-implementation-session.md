2026-09-27. The user and their remote friend are referred to as **the two little rascals** in testing and development updates.

## Implemented in the separate Enhanced engine

- `cof_story_coop 1` opts into exact-stock-DLL-verified story behavior. The stock game DLL remains unchanged on disk. The six-byte multiplayer transition veto is temporarily bypassed in memory; the landmark argument and relocation records remain intact. Shutdown restores the instruction bytes before DLL unload.
- Multiplayer landmark transitions capture per-client identities and inventory ownership, use existing world snapshots, exclude stale destination player/inventory records, and preserve the client netchannel during sign-on. Missing prerequisites reject before map teardown. Each captured client must become ready or disconnect before the world resumes.
- Party code detects actual phone/knife possession from `inventorySlot[7]` at retail player offset `+0x21FC`, using slots 1–6 and exact descriptor paths. It grants missing starter items using normal game callbacks and confirms actual slot possession. The legacy classname array at `+0x2234` is unpopulated and is no longer used. General key-item replication is not implemented.
- Party door recovery caches an actual inter_door event, waits for its owner to arrive at the matching exit, and finds collision-safe companion landings. Temporary camera/freeze states wait within the deadline; dead or displaced clients are cancelled. Door-caused invisibility is cleared only with a prior visible identity-matched baseline and an otherwise playable completed exit.
- Transmitted player model userinfo selects `cof_s1` for slot 0 and `cof_s2` for subsequent slots, only when the local generated asset exists. Replacements are atomic and reserve the terminating zero. The original game entity model and gameplay callbacks remain unchanged.
